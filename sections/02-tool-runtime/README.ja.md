# 2 · Tool runtime

[English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · **日本語** · [한국어](README.ko.md)

> 機能を追加するということは、ツールを登録することを意味します。ループはそのままです。

agent loop はツールを通じてのみ機能します。モデルは、`name` および `input` を含む構造化された `tool_use` ブロックを出力します。

harness は、その名前をコードにマップします。入力を検証し、ハンドラーを実行して、結果を返します。

runtime は次のことを行う必要があります。

1. モデルにどのツールが存在するかを伝えます。
2. 各ツールの入力スキーマを説明します。
3. 各 `tool_use` を名前でルーティングします。
4. 可能な場合は、安全な呼び出しを並行して実行します。
5. 大規模なツール カタログを見つけられるようにしておきます。

この層がないと、モデルは動作を要求できますが、そのアクションを実行できるものはありません。

`bash` ツールが 1 つだけあれば、すべての機能が文字列処理になります。ツールごとの検証や許可ロジックはありません。

ここから2つの失敗が始まり、モデルのせいになります。 2 つの説明が重複しているため、間違ったツールが選択されます。 harness が入力を書き換えたため、編集は失敗します。

## メカニズム

![機構図](assets/02-tool-runtime.png)

ツールは、名前、ハンドラー、スキーマ、およびいくつかの述語を持つ小さなオブジェクトです。レジストリにはツールが名前で保存されます。ディスパッチは検索です。

### 新しい: tool runtime

```python
@dataclass
class Tool:                                  # src/tools.py
    name: str
    run: Callable[[dict], Any]
    description: str = ""                      # advertised to the model
    input_schema: dict = ...                   # the Anthropic schema it accepts
    is_read_only: bool = False
    is_concurrency_safe: bool = False         # may batch in parallel
    is_edit: bool = False                     # read by the gate (section 3)

class Registry:                              # src/tools.py
    def register(self, tool): self._tools[tool.name] = tool   # add a handler
    def get(self, name):      return self._tools.get(name)    # dispatch = lookup
    def schemas(self):        ...             # the tools list handed to the model
```

- ツールはデータクラスです。
- レジストリは `name -> tool` です。
- ケイパビリティの追加とは、ハンドラーを 1 つ登録することを意味します。
- `schemas()` は、モデルにアドバタイズされたツール リストを返します。
- `run_concurrently` は、`is_concurrency_safe` とマークされたツールをバッチします。
- 安全でない呼び出しは順序どおりに行われるため、書き込みが競合することはありません。

### 統合方法

セクション 1 では、インライン `HANDLERS` dict を使用しました。セクション 2 では、`registry` をループに渡し、各 `tool_use` から `_dispatch` までをルーティングします。

```python
def run_turn(messages, model, registry, max_steps=10): # src/loop.py (now takes a registry)
    ...
    results = [_dispatch(b, registry)                   # was: run_tool(call)
               for b in response.content if b.type == "tool_use"]
    messages.append({"role": "user", "content": results})

def _dispatch(block, registry):              # resolve, run, wrap as a tool_result
    tool = registry.get(block.name)           # name -> tool
    content = run_tool(tool, block.input)
    return {"type": "tool_result", "tool_use_id": block.id, "content": content}
```

それ以外の場合、ループ本体は変更されません。ディスパッチステップのみがレジストリを使用するようになりました。

`_dispatch` は次の拡張ポイントです。セクション 3 では、そこに許可ゲートを追加します。セクション 4 では、そこに hooks を追加します。

わかりやすくするために、デモは順番にディスパッチされます。実際のランタイムは安全な呼び出しをバッチ処理し、オンデマンドで大規模なツール スキーマを読み込みます。

### さらに読む

これは `src/` にはありません。これは、ai-agent-book および tool use に関する出版物からのものであり、表内のシステムについては確認されていません。
Claude Code という名前が付けられている場合、コントラストは独自のソースから得られます。

**グループ化。** ツールは、通話の発信先と通話内容に応じて 5 つのグループに分類します。

- **知覚**は外の世界を読み取ります。
- **実行**すると変更されます。
- **コラボレーション**が別のエージェントに到達します。
- **イベント トリガー**により、外部の世界がエージェントを起動させます。
- **ユーザーコミュニケーション**はその人に届きます。

5 つのグループのうち 4 つは後で独自のセクションを取得します。セクション 6、12、16 ではコラボレーションを構築します。セクション 13 と 14 ではイベント トリガーを構築します。
セクション 19 ではユーザー チャネルを構築します。このセクションでは、5 つすべてが存在するレイヤーを構築します。
コントラクトが異なるため、グループ化が維持されます。認識呼び出しは繰り返して安全にバッチ処理できますが、実行呼び出しはそうではありません。

**粒度** エージェントが PDF、Word ファイル、スプレッドシートを読み取る必要があるとします。ツールは 1 つですか、それとも 3 つですか?

同じ種類の入力に対して同じ作業を行う場合は、それらをマージします。型パラメーターを持つ 1 つの `read_document` は、ほぼ同一のリーダー 3 つよりも簡単に選択できます。
パラメータが重なり合わなくなったら分割します。無関係なフィールドを結合するスキーマでは、どのフィールドが適用されるかを判断できないため、モデルは間違ったフィールドを埋めます。

**説明クラフト。** `description` は、ツールを選択する前にモデルが読み取る唯一のテキストです。それは人間のためのドキュメントではありません。

役に立つものは次の 5 つのことをカバーしています。

- ツールをいつ使用するか。
- 使用しない場合。
- 各パラメータの実数値。
- 戻ってくるものの形。
- 通話料はどれくらいかかりますか。

いくつかの実際の例は、別の散文の段落よりも役に立ちます。この本では、それらを追加することで大きな利益が得られると報告しています。
この図には引用がないので、サイズではなく方向を理解してください。

**パラメータの忠実度。** モデルは、検索テキストに中引用符が含まれる編集を送信します。ハンドラーに向かう途中で、harness がそれをまっすぐにします。

編集は失われ、モデルは文字列が一致しなかったことだけを認識します。正しい入力が送信されたため、トランスクリプトにはギャップを説明するものはありません。
ルールは次のとおりです: 入力をそのままハンドラーに渡します。不適切な入力を拒否し、その理由を述べます。決して書き直さないでください。また、モデルが書き込まなかった引数を追加しないでください。

**チェックリスト パラメーター。** 返金ツールは、ハンドラーが決して使用しない `expected_price` を受け取ります。

それを書き留めることがすべてのポイントです。モデルは、呼び出しを実行する前に、信じている価格を宣言する必要があります。
ハンドラーは保存されている価格を読み取り、それを決定し、両者が異なる場合はログに記録します。
したがって、最後のチェックは、モデルが偽造できないデータに基づいて行われます。 τ ベンチ スコアも同様に実行されます。つまり、エージェントが実行したと述べたものではなく、最終的なデータベースの状態を読み取ります。

**認識インターフェイス** 大規模なリポジトリの検索では 4,000 行が一致しますが、コンテキストに適合するのは最初の 50 行だけです。

次の 3 つのルールにより、結果が正確に保たれます。

- 検索では、1 ページの候補とカーソルが返されます。
- 読み取りにはオフセットと制限が必要なため、モデルは長いファイルを実行できます。
- 結果では切り捨てにラベルが付けられます。

サイレントカットはエラーよりも悪いです。モデルは部分ファイルを全体であるかのように読み取り、後のすべてのステップでギャップを継承します。

コード検索により選択肢が表示されます。 4 つのアプローチがあり、1 つだけを使用するシステムはありません。

|アプローチ |発見 |コスト |
| --- | --- | --- |
| **グローブ** |パスパターンによるファイル。 |内容については何もありません。 |
| **グレップ** |行番号付きの正確な文字列と正規表現。 |クエリを絞り込むための複数の呼び出し。同義語が欠落しています。 |
| **埋め込みインデックス** |意味に基づいてコード化するため、平易な言語のクエリが得られます。 |構築して同期を保つためのインデックス。不透明なランキング。 |
| **LSP シンボル** |定義、参照、型、正確に。 |言語ごとの言語サーバー。 |

Claude Code と Cursor は、そのテーブルの反対側の端にあります。 Claude Code はインデックスを提供せず、glob、grep、read と段階的に検索します。
モデルでは呼び出し間のクエリを絞り込みます。この本では、代わりにインデックスを構築するために Cursor が支払うことについて説明しているため、平易な言語のクエリが必要になります。
識別子を指定しないコードを見つけることができます。

編集も同様に分割します。何が変わったかを伝える 5 つの方法:

|スキーム |モデルは | を出力します。トレードオフ |
| --- | --- | --- |
| **差分と適用モデル** | 2 番目のトレーニング済みモデルによって書き直された、大まかなスケルトンの差分。 |速くて寛容。 2番目のモデルが必要です。 |
| **古い文字列と新しい文字列** |検索する正確なテキストとその場所に配置するテキスト。 |明確であり、大声で失敗します。最初に新しく読む必要があります。 |
| **行番号** |範囲とその代替品。 |コンパクト。以前の編集によりファイルが移動されると、失効します。 |
| **エディタのコマンド** | vim スタイルの小さなコマンド言語。 |簡潔です。間違える構文がもう 1 つあります。 |
| **アンカー** |開始マーカーと終了マーカー。 |シフトを生き延びます。マーカーが繰り返される場合はあいまいです。 |

同じ 2 つのシステムが編集時に再び分割されました。 Claude Code は、まったく古い文字列を置き換えて、モデルに最初にファイルを読み込ませます。
そのため、間違った行を編集する代わりに、古い文字列は大声で失敗します。この本では、Cursor が代わりに大まかなスケルトンを送信すると説明されています。
2 番目のトレーニング済みモデルがそのファイルを書き換えて、そのルートをより高速なルートとして報告します。

**早期開始とカスケード中止** 呼び出しはバッチの残りの部分を待つ必要はありません。自身の引数の解析が終了した瞬間に開始できます。

モデルはまだ後の呼び出しを書き込んでいるため、初期の呼び出しのレイテンシーは生成内に隠されます。これにはスピードが必要ですが、失敗に対するルールが 1 つ必要です。
エラーが発生すると、それに依存する呼び出しが停止します。同じバッチ内の独立した呼び出しは実行され続け、親ターンも同様に実行されます。

**シェルの状態。** 1 つの呼び出しで `cd build` が実行され、仮想環境がアクティブ化されます。次の呼び出しでもどちらかが表示されますか? 2 つのデザインがあり、どちらも防御可能です。

- **呼び出しごとにリセット。** Claude Code の bash ツールは、呼び出しの間にライブ シェルを保持しません。 1 回の呼び出しで設定された変数とシェル関数は、次の呼び出しでは失われます。
  ツールの説明では、モデルに絶対パスを使用するように指示されます。各呼び出しは独自に再生され、並列呼び出しが相互に漏れることはありません。
- **1 つの永続セッション。** この本では共有端末をデフォルトにしているため、`cd`、エクスポートされた変数、およびアクティブな仮想環境はすべて存続します。
  別々のシェルは並行作業に使用できます。モデルが繰り返すセットアップ コマンドの数が減り、harness は追跡およびリセットするためにセッション状態を取得します。

**大規模な検出。** 接続された 20 台のサーバーが何百ものツールを提供しますが、その完全なスキーマはプロンプトに収まりません。

したがって、レジストリは最初に名前を送信し、何かが要求された場合にのみ完全なスキーマをロードします。質問は平易な言葉でモデルから得られます。
MCP-Zero は、エージェントにどの機能が欠落しているかを言わせ、それをサーバーと照合し、次にそのサーバー上のツールと照合し、一致したスキーマのみを挿入します。
モデルはツールの存在を知る必要はありませんでしたが、キーワード検索ではそれができません。

**キャッシュセーフなロード。** ロードされたスキーマがコンテキスト内のどこに配置されるかによって、コストが決まります。

最後に一度追加し、そのままにしておきます。プロンプトの先頭にあるツール ブロックを編集すると、キャッシュされたプレフィックスとその後のすべてのトークンが無効になります (セクション 10)。
追加すると接頭辞はそのまま残され、次のターンではスキーマが通常の履歴に変わります。

## システムごと

各エージェントがツールを定義し、呼び出しをルーティングし、並列処理を処理し、大規模なカタログを公開する方法。

| | Claude Code | mini-swe-agent | deepseek-harness |
| --- | --- | --- | --- |
| **長所** |ツールごとの検証、権限、並列処理、遅延検出。 | `bash` ツール 1 つ、小型 runtime、カタログなし。 |エージェントごとのツールセット。呼び出しごとに 1 つの監査パイプライン。 |
| **短所** |すべてのツールには契約が必要です。 |ツールごとの検証や権限はありません。ゲートは 1 つのコマンド文字列を認識します。 |単純なツールであっても、出力コントラクトを宣言する必要があります。 |
| **理由** |機能ごとに 1 つの新しいツール。ループはそのままになります。 |すべてのアクションはシェル コマンドであるため、1 つのツールで十分です。 |スコープごとに 1 つのリゾルバーが検索、ディスパッチ、表示をフィードします。 |
| **方法: ツール定義** |スキーマ、ハンドラー、述語。 | 1 つの `bash` スキーマ、1 つのコマンド フィールド。他の名前のエラー。 |スキーマ、型付き出力コントラクト、本文、純粋なプレゼンター。 |
| **方法: 発送** | MCP を使用した、アクセス許可でフィルターされたプールのエイリアス検索。 |レジストリがありません。すべての呼び出しはシェル コマンドです。 |スコープ付きルックアップ、その後 5 段階の保護されたパイプライン。 |
| **方法: 並列呼び出し** |安全な通話バッチ。一人で走るのは危険です。フラグはデフォルトでオフです。 |いいえ。テキスト モードでは、応答ごとに 1 つのアクションが実行されます。 |呼び出しごとに分類され、排他的にフェールクローズされます。 |
| **方法: 発見** |最初に名前を付けます。名前またはキーワードによるリクエストに応じて完全なスキーマがロードされます。 |ツールが 1 つあれば不要です。 |遅延読み込みはありません。制限とプリセットによって各スコープが形成されます。 |

## 障害モード

- **不明なツール名。** モデルには、欠落しているツールまたは無効なツールの名前が付けられています。ループをクラッシュさせる代わりに、`tool_result` エラーを返します。
- **スキーマのドリフト。** スキーマは 1 つのことを示し、ハンドラーは別のことを期待します。発送前に検証します。
- **安全でない並列処理。** 2 回の書き込みにより、同じファイルが破損する可能性があります。ツールが安全であることがわかっている場合を除き、デフォルトはシリアル実行になります。
- **カタログ オーバーフロー。** ツール スキーマが多すぎると、プロンプトが混雑する可能性があります。必要になるまで完全なスキーマを延期し、キャッシュされたプレフィックスが残るように最後にロードされたスキーマを追加します。
- **結果が大きくなります。** 大きな出力では、context window を満たす可能性があります。結果をキャップし、完全な出力を保持し、プレビューとパスを返します。
  切り口にラベルを付けます。サイレント ファイルでは、モデルは部分的なファイルを全体であるかのように読み取ったままになります。
- **間違ったツールが選択されました。** 2 つの説明が重複しているか、1 つのツールが 2 つのジョブを実行します。重複をマージし、過負荷になったスキーマを分割し、各ツールが何に適していないのかを説明します。
- **サイレント入力ドリフト。** harness は、ハンドラーへの途中で引数を正規化または追加します。呼び出しは失敗し、モデルはその理由を判断できません。理由を付けて不適切な入力を拒否します。
- **バッチの失敗は広がります。** 並列バッチ内の 1 つの呼び出しが失敗すると、ターン全体が無効になります。それに依存する呼び出しのみを中止します。

[`src/`](src/) は 01 を前方に繰り上げて次を追加します。

python sections/02-tool-runtime/src/test.py         # offline checks, no key
uv run python sections/02-tool-runtime/src/demo.py  # live demo, needs a key
